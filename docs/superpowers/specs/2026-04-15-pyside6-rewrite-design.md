# PySide6 地图导航重写设计

## 背景

当前仓库的 Tk + OpenCV 工具已经验证了核心能力可行：

- 从屏幕上的小地图区域持续截图
- 使用 ORB 将小地图实时定位到大地图
- 在独立窗口中显示当前位置

但现有实现把启动、截图、定位、GUI、缓存、配置、资源点与错误处理揉在单文件中，难以继续扩展导航能力。新的目标不是重构旧代码，而是借鉴已有行为，用 `PySide6` 重写一个新的导航底座。

## 目标

第一阶段交付一个可运行的 PySide6 桌面工具，具备以下能力：

- 加载大地图、资源点与必要配置
- 通过手动框选确定小地图截图区域
- 持续截图小地图
- 使用可替换的定位算法接口，首版实现 ORB 定位
- 在 PySide6 窗口中显示北向固定、可缩放的跟随视图
- 在视图中持续显示当前位置
- 在视图中显示资源点图层
- 支持短时定位失败的状态反馈与手动重置

## 非目标

第一阶段不做以下内容：

- 自动识别游戏窗口并按相对坐标截图
- 路线规划与导航指令
- 路线编辑器
- 复杂资源点筛选面板
- 大量自动化测试
- 保留旧 Tk 代码结构或兼容旧入口

## 用户确认的产品决策

- 使用 `PySide6`
- 截图方式采用策略模式，第一版只做“手动框选屏幕区域”
- 地图窗口采用地图优先的跟随视图
- 视图支持缩放
- 地图朝向固定为北向，不跟随角色旋转
- 定位层采用策略模式，第一版只实现 `ORB`
- 第一版资源点图层可显示
- 新分支上允许整仓重写，旧实现可以删除
- 自测优先采用“从大地图裁出小图作为定位输入”的方式
- 测试算例只保留最小必要量，不为覆盖率额外堆测试

## 架构概览

采用模块化单进程架构。UI、截图、定位、资源加载与图层解耦，但运行时仍是一个桌面进程。

### 核心模块

- `main.py`
  应用入口，创建 `QApplication` 并装配主窗口
- `app/window.py`
  主窗口与基础 UI 组件
- `app/controller.py`
  主流程调度层，连接截图、定位与视图刷新
- `capture/base.py`
  `CaptureStrategy` 接口
- `capture/manual_region.py`
  手动框选截图策略
- `locator/base.py`
  `LocatorStrategy` 接口
- `locator/orb_locator.py`
  ORB 定位实现
- `map_view/view.py`
  北向固定、可缩放的跟随视图
- `layers/resources.py`
  资源点图层
- `models/types.py`
  `FrameData`、`LocationResult`、`ResourcePoint` 等数据结构
- `services/assets.py`
  地图、图标、资源点与缓存的加载
- `services/config.py`
  配置读写

## 数据流

运行时数据流如下：

1. 应用启动，读取配置与地图资源
2. 若无截图区域配置，进入手动框选
3. `CaptureStrategy` 持续输出小地图帧
4. `LocatorStrategy` 接收帧并输出定位结果
5. `Controller` 根据定位状态更新应用状态
6. `MapView` 根据最新位置刷新跟随视图
7. `ResourceLayer` 在当前视野中绘制可见资源点

## UI 设计

第一阶段主窗口采用“地图优先”布局：

- 中央是地图跟随视图
- 状态信息采用悬浮信息块或状态栏显示
- 资源点图层可开关显示
- 缩放围绕当前玩家位置展开

### 首版交互

- 选择小地图区域
- 开始 / 暂停跟踪
- 重置定位
- 滚轮缩放地图
- 资源点显示开关
- 状态栏显示定位状态、缩放倍率、最近一次成功定位时间

## 应用状态

采用显式状态，避免流程散落在 UI 逻辑中。

- `Unconfigured`
  没有截图区域，等待框选
- `Ready`
  资源已加载，可开始跟踪
- `Tracking`
  正在截图、定位和刷新视图
- `Lost`
  连续若干帧无法稳定定位
- `Error`
  资源缺失、截图失败或初始化失败

## 截图策略设计

### `CaptureStrategy`

统一接口：

- `start()`
- `stop()`
- `current_frame()`

第一版实现 `ManualRegionCaptureStrategy`：

- 首次启动进入区域框选
- 保存屏幕区域配置
- 后续持续按固定区域截图

后续可以新增：

- `WindowBoundCaptureStrategy`
- `TestImageCaptureStrategy`

## 定位策略设计

### `LocatorStrategy`

统一接口：

- `initialize()`
- `locate(frame) -> LocationResult`
- `reset()`

### `LocationResult`

至少包含：

- `x`
- `y`
- `found`
- `confidence`
- `mode`
- `timestamp`

### ORB 首版策略

复用现有项目中已经验证过的核心思路，但做结构化拆分：

- 加载大地图
- 加载或构建特征缓存
- 提取小地图特征
- 优先局部搜索
- 连续失败后回退全图搜索
- 使用仿射估计得到最终位置
- 对跳变结果做约束

内部建议拆为以下私有步骤：

- `_load_map_assets()`
- `_load_or_build_feature_cache()`
- `_extract_minimap_features()`
- `_select_search_scope()`
- `_match_features()`
- `_estimate_position()`
- `_validate_result()`

## 线程模型

采用 `QThread + worker object`，而不是在主窗口里直接管理 Python 线程。

### `CaptureWorker`

- 周期性截图
- 只保留最新帧
- 通过信号发出图像帧

### `LocateWorker`

- 接收最新帧
- 执行定位
- 发出 `LocationResult`

### 主线程

- 处理 UI 更新
- 接收定位结果
- 切换应用状态
- 响应用户交互

## 地图视图与图层

### `MapView`

职责：

- 显示地图底图
- 维持玩家为中心的跟随相机
- 处理缩放
- 承载图层渲染

规则：

- 北向固定
- 玩家尽量保持居中
- 丢失时停留在最后有效视角

### `ResourceLayer`

第一阶段只做显示：

- 加载资源点
- 按地图坐标绘制
- 支持视野裁剪
- 支持开关显示

图层顺序：

1. 地图底图
2. 资源点图层
3. 玩家位置图层
4. 未来路线图层
5. 未来导航提示图层

## 配置、资源与缓存

职责分离如下：

- `config/`
  用户运行配置，例如截图区域、缩放倍率、资源路径
- `assets/`
  原始地图、图标、资源点数据
- `cache/`
  可重建产物，例如 ORB 特征缓存

原则：

- 配置缺失时自动生成默认值
- 缓存缺失或损坏时自动重建
- 资源缺失时给出清晰错误

## 错误处理

第一阶段采用直接、可诊断的错误处理：

- 地图缺失：阻止进入跟踪并提示
- 资源点缺失：允许启动，但图层不可用
- 截图失败：状态栏提示并自动重试
- ORB 缓存损坏：自动重建
- 连续定位失败：进入 `Lost`
- 用户未完成框选：停留在配置态

## 验收标准

满足以下条件即可视为第一阶段完成：

- 能成功框选小地图区域
- 能持续截图
- 能完成 ORB 定位
- 能在 PySide6 视图中持续显示当前位置
- 能缩放地图且视图围绕玩家位置更新
- 能显示资源点图层
- 丢失定位时能正确反馈状态
- 能手动重置定位
- 代码结构已摆脱旧 Tk 单文件模式

## 验证策略

验证以功能验收为主，不追求大量测试文件。

### 必要验证

- 应用能启动
- 能完成区域框选并保存配置
- 能加载地图与资源点
- 能显示跟随视图与资源点
- 能处理重置定位与定位丢失

### 自测优先方式

优先使用大地图裁剪小图来做算法自测：

- 从大地图中按真实比例裁出若干小图
- 将其作为小地图输入送入定位器
- 检查定位结果是否落回原始坐标附近

此方式可在不依赖真实游戏窗口的情况下快速验证核心定位链路。

## 分支与迁移策略

- 在独立重写分支上推进
- 允许删除旧 Tk 实现
- 新项目不以“兼容旧结构”为目标
- 旧仓库主要作为功能参考与算法参考

2. 落配置、资源与缓存服务

4. 落 ORB 定位策略
5. 落 `MapView` 与玩家位置显示
6. 接入资源点图层
7. 完成状态栏、重置与错误反馈
8. 使用“大地图裁小图”做最小必要自测
